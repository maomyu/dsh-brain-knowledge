# 大脑 · DeepSeek Harness 插件

大脑复用 Dao bot 提交 `4499dd6002911d1f452c6335bb2ac76b04fc740e` 的知识、任务、目标、文档审查和逻辑工作区模块。使用原有侧栏「大脑」、项目对话和 `/goal`。

## 安装

目标宿主为 DeepSeek Harness `0.2.2-rc.1`。在源码目录运行 `npm ci` 即可构建，也可以在 Harness 的「插件 → 添加插件」中选择预构建的 `.tgz`。退出并重新打开 Harness 后生效。

## 沉淀规则

- 普通对话沿用 Dao bot 的证据核对、旧页对照和保留策略。新增和改写经独立证据审核与一致性审核。
- 任务确认时绑定本次沉淀授权、执行器和可选审查资料。执行结果先固定来源、报告或文件版本，再进入审查。已有页面上的候选形成提案，新的草稿核对目录并再次确认后才能发布。
- 项目对话的 `/goal` 进入 Dao 目标流程。计划签署绑定项目、可写页面、审查设置和可调度模型。改签后保留旧任务记录，旧授权不会带入新计划。
- 对话读取所属逻辑工作区内的项目知识。任务回传的工具策略只查询原对话所属工作区的任务卡。

知识保存在各项目的 `brain/`。早期插件的 JSON 条目可继续查看和归档。路径重合时以项目 Markdown 为准。模型审查可能产生模型用量。

## 任务执行器与终端

任务卡可以选择 Harness、Codex 或 Claude Code。Codex 可加载本机模型目录，Claude Code 可填写本机支持的模型和推理力度。研究、文档与编码任务的权限沿用 Dao bot 的类型约束。目标审批时可将原生模型加入子任务调度池。

在 macOS 的普通编码任务卡里，选中 Codex 或 Claude Code 后可以确认交接到系统终端。交接会保存私有启动资料、任务回执和限于原项目的只读大脑授权。更换知识位置或移除项目会撤销授权。已有隔离工作树的任务也可以打开终端，带有原生会话身份的失败任务可以继续。终端交接使用本机已安装、可由终端找到的 `codex` 或 `claude`。系统终端回执只表示已交接。

## 文档导入审查

在「大脑」选择项目，再打开「导入文档审查」。可以选择或拖入 PDF、DOCX 或文本，指定项目或所属逻辑工作区，选择只读或独立审查并沉淀。服务保留原件、转换覆盖范围和提交回执；审查结果在对应的对话中查看。PDF 与 DOCX 可在离线预览中核对原件。编码任务可选用已保留的资料作为独立审查证据。

## 逻辑工作区

原有项目保留在个人工作区。额外逻辑工作区通过当前 profile 的插件配置声明。项目路径需是已存在的绝对路径。已归属其他工作区的项目会拒绝重复登记。

```yaml
- id: brain-knowledge
  config:
    directory: !!js dshHomePath('brain-knowledge')
    spaces:
      - id: 11ac4207-f1dc-461c-89fa-d4fb70de08b1
        title: 运营组
        projects:
          - path: /absolute/path/to/project
            title: 运营项目
```

源码基线、适配与第三方授权文本位于 `vendor/`。Harness 的版本适配全部由插件配置与模块承载。
