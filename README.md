# 大脑 · DeepSeek Harness 插件

大脑复用 Dao bot 提交 `4499dd6002911d1f452c6335bb2ac76b04fc740e` 的知识、任务、目标和逻辑工作区模块。日常从项目对话提出任务或使用已有的 `/goal`。对话内显示相应的确认和审查卡，侧栏「大脑」显示正文、来源、时间线、旧版本和待处理提案。

## 安装

目标宿主为 DeepSeek Harness `0.2.2-rc.1`。在源码目录运行 `npm install` 即可构建。也可以在 Harness「插件 → 添加插件」中选择预构建的 `.tgz` 安装包。目录和安装包都走 Harness 的插件加载层。退出并重新打开 Harness 后生效。

## 沉淀规则

- 普通对话沿用 Dao bot 的证据核对、旧页对照和保留策略。新增和改写经独立证据审核、一致性审核，审核记录和写入回执可追溯。
- 任务确认时保留本次的沉淀授权。执行结果先固定来源、报告或文件版本，再进入相应审查。候选写到已有页面时形成提案，另存的新页草稿要核对正式目录并再次确认后才可发布。
- 项目对话的 `/goal` 进入 Dao 目标流程。签署版本绑定项目、可写页面和审查设置。完成证据、目标任务和知识回执按原规则校验，改签后的旧任务记录保留。已有 Harness 原生目标继续由原命令处理。
- 对话读取所属逻辑工作区内的项目知识，默认写入由原版执行范围决定。目标签署的范围与项目归属会在写入时重新核验。侧栏按逻辑工作区展示，应用所有者可以查看全部项目。

任务回传的工具策略只查询原对话所属工作区的任务卡，其他工作区的任务卡不会参与该次审查。

模型审查可能产生模型用量。项目知识保存在各项目的 `brain/` 中。早期插件的 JSON 条目可继续查看和归档。路径重合时以项目 Markdown 为准。

## 逻辑工作区

原有项目保留在个人工作区。额外逻辑工作区可通过 Harness 当前 profile 的插件配置声明。下面是对应的 `cordis.patch.yml` 配置。标识应稳定，项目路径必须是已存在的绝对路径，已归属其他逻辑工作区的项目会拒绝重复登记。可通过 `conversations` 绑定已存在的无项目对话。

```yaml
- id: brain-knowledge
  config:
    directory: !!js dshHomePath('brain-knowledge')
    spaces:
      - id: 11ac4207-f1dc-461c-89fa-d4fb70de08b1
        title: 运营组
        projects:
          - path: /absolute/path/to/project
            title: 运营项目
        # conversations:
        #   - session-00000000-0000-4000-8000-000000000000
```

源码基线及 MIT 授权文本位于 `vendor/`。Harness 的兼容配置集中在插件的配置文件和适配代码中。此安装包面向 Harness 内执行和审查。Dao bot 的原生终端交接、专用文档导入审查以及 Codex、Claude 的执行选择界面依赖各自宿主能力。
